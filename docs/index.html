Does Knowing a Content Item's Archetype Help Predict Whether It's Underperforming?

Abstract

This study asks whether an unsupervised content archetype — a behavioral cluster learned from position, engagement, and content signals — improves prediction of click-through performance beyond raw metrics alone. Using one mid-panel month of pseudonymized FlyRank warehouse data (content-month grain, gsc_and_ga4-access clients), a Random Forest classifier was compared against a transparent position-benchmark baseline on an identical client-grouped split. The model reached an honest 0.927 AUC, while the baseline's higher 0.963 AUC was found to be near-circular with its own target — and the archetype cluster itself contributed almost no predictive value (0.0013 combined importance). The output is a ranked, human-reviewed content action queue, not an autonomous system.

01

Introduction

Content teams generate more pages than any editor can manually triage. FlyRank's internal workflow uses hand-written flags (staleness, CTR-fix, quick-win) to prioritize review — this study checks whether those flags' underlying assumptions hold on a real warehouse slice, then asks a harder question: does the internship's own capstone lane, unsupervised archetype clustering, actually add predictive value on top of what's already measurable?

The decision this supports: which content items a human editor reviews first, and for what kind of fix. The cost of a wrong call is a wasted review cycle, not a irreversible action — every recommendation below is explicitly reviewed by a person before anything changes.

02

Data

Release: FlyRank internship-warehouse (Hugging Face, gated, ~79M rows across tables). Tables: dim_content, dim_clients, fact_content_daily_performance (partitioned by month=YYYY-MM). Window: one mid-panel month (2026-03), filtered to gsc_and_ga4-access clients, published and non-deleted content only.

Deliberately excluded

  • fact_content_query_90d — different grain and fixed window, not used this lane
  • provider_used, model_used — operational metadata, not a behavior signal
  • content_updated_date, last_optimized_date, optimization_eligible_date — can be set after the decision month; unverifiable point-in-time risk
  • All hash-ID columns — used for joins/grouping only, never as model features
  • The sealed final month (2026-06) — referenced only to demonstrate leakage, never to build features or labels
Public-safety pass No client names, raw URLs, or query text appear anywhere in this pipeline — every identifier is a pseudonymous hash from the warehouse itself.
03

Methodology

Target (proxy): high_performer = avg_ctr > median(avg_ctr), thresholded within the month — unsupervised-adjacent, since no ground-truth performance label exists in the warehouse.

Features (12): position, impressions, on-site engagement ratios, AI-referral share, content age, word count, search volume, competition, one-hot content type / intent, and a KMeans (k=6) archetype cluster label. avg_ctr itself is excluded — it defines the target, so including it would be circular.

Baseline: score = expected_ctr_for_position_bucket − actual_ctr, a transparent single-signal rule, matching FlyRank's own CTR-fix flag logic.

Validation: client-grouped split (GroupShuffleSplit on client ID, confirmed zero overlap) — avoids the model memorizing client-specific editorial style instead of a generalizable pattern.

Leakage checks: a deliberate sealed-month leak trap, a naive-random-split vs. grouped-split comparison, and a scan confirming no excluded/operational field reached the final feature set.

04

Results

MethodAUC
Baseline rule (single signal) 0.963
Random Forest (full features + archetype cluster) 0.927
Read carefully The baseline's higher AUC is not a stronger result. corr(baseline_score, avg_ctr) = -1.000 on the held-out split — the baseline score is a near-exact linear rescaling of the target itself. The model's 0.927, built entirely from features independent of the target, is the trustworthy number here.

What the model actually leans on

Permutation importance is dominated by total_impressions (0.153) and sessions_per_impression (0.074). The archetype cluster's combined importance was 0.0013 — effectively zero. Clustering content into behavioral archetypes did not meaningfully help predict CTR performance in this test.

Error profile

13.8% misclassified on a 32,446-row held-out test set. A deliberate leak trap (injecting a sealed future month's click count) did not inflate this model's score (0.925 with the leak vs. 0.927 honest) — unlike a simpler logistic-regression version of the same test, where the leak did jump the score, this ensemble's existing features already captured most of the available signal.

05

Limitations & Honest Framing

  1. Baseline AUC is inflated by near-circularity, not genuine predictive skill.
  2. Archetype clustering did not earn a predictive role — a genuine negative result, reported as one.
  3. Single cross-sectional month; nothing here distinguishes a consistently weak page from one having a quiet month.
  4. No true sealed holdout evaluation was run — the final month is referenced only to demonstrate leakage, not to produce a blind evaluation.
  5. Every relationship reported is observational/correlational — no causal design, no claim of "why," only "what was observed."
  6. Scoped to gsc_and_ga4-access clients, one month, one client mix — not a guarantee for a different month or client base.

Ranked Recommendations

Two layers, from the action playbook: item-level review candidates (position-benchmark rule) and archetype-level action mapping (read off each cluster's own profile, not hand-picked).

01
REVIEW_TITLE_META

Items whose CTR falls meaningfully below their own position tier's benchmark — highest-confidence, most reproducible signal in this study.

02
REFRESH_CANDIDATE

Archetype clusters skewing older and below-median CTR — directionally consistent with FlyRank's own portfolio-level refresh findings.

03
DISTRIBUTE_SUPPORT

Clusters already ranking well with strong CTR — protect and amplify rather than rebuild.
